# mtpctl

MTProto-прокси для Telegram ([telemt](https://github.com/telemt/telemt)) по схеме «мастер + входы» с веб-кабинетом.

- **Мастер** — хост, с которого доступен Telegram. На нём база SQLite, кабинет и свой экземпляр telemt на каждый сервер.
- **Входы** — любые хосты, к которым подключаются клиенты. Это только TCP-пересылка на мастер без расшифровки:
  ни ключей, ни данных на них нет.
- **Пропал вход** — ставите новый за минуту.
- **Переезд мастера** — переносите один файл базы.

```
клиент ─ домен сервера ─→ ВХОД (nginx stream)                 МАСТЕР
         (A-запись на IP    443 ─PROXY protocol─→ мастер:порт ─→ telemt@<сервер> ─→ Telegram
          входа)            80  ──────────────→ мастер:80     (Let's Encrypt, редирект на https)

на мастере всё «не-Telegram» (браузер, проверки DPI) → nginx: заставка домена и кабинет на секретном пути
```

## Установка мастера

Одной строкой, от root:

```sh
bash <(wget -qO- https://raw.githubusercontent.com/mittus/mtpctl/master/install.sh)
```

Установщик генерирует пароль и **секретный путь кабинета** и печатает их один раз. Логина нет — вход
только по паролю:

```
════════════════════════════════════════════════════════════════
  Мастер mtpctl установлен
════════════════════════════════════════════════════════════════
  Пароль:         Vt8sLq2NcR6yHd4E
  Путь кабинета:  /aZ7kQ2mW9xPc4LrT8e/
  Адрес мастера:  <IP мастера>  (для команды установки входов)
  Кабинет:        откроется на https://<домен сервера>/aZ7kQ2mW9xPc4LrT8e/ после добавления первого сервера
════════════════════════════════════════════════════════════════
```

**Свои значения вместо случайных.** Задайте их в ответ на вопросы установщика или переменными окружения
`MTPCTL_PASSWORD`, `MTPCTL_WEB_BASE_PATH`, `MTPCTL_PANEL_DOMAIN`.

**Параметры:**
- `--addr IP|DNS` — адрес мастера для входов. По умолчанию определяется публичный IP.
- `--panel-domain DNS` — отдельный домен кабинета, см. «Домен кабинета» ниже.
- `--restore копия.db` — перенос мастера из копии базы.

**Что ставится:**
- nginx со stream, certbot, python3 (только стандартная библиотека);
- telemt нужной версии: скачивается с GitHub, sha256 зашит в `install.sh`.

Поддерживаются Debian 10–13 и Ubuntu 20.04+ (amd64 и arm64).

**Повторный запуск** установщика и обновление (см. «Обновление») ничего не теряют.

Удаление: `mtpctl uninstall`. Копия базы при этом остаётся в `/root`.

### Где что лежит

| Что | Где |
|---|---|
| Всё своё | `/opt/mtpctl`, это домашний каталог системного пользователя `mtpctl` |
| Код | `/opt/mtpctl/app` (root, только чтение) |
| База (единственный источник истины) | `/opt/mtpctl/data/mtpctl.db`: серверы, клиенты с ключами, трафик, хэш пароля кабинета |
| Рабочая копия базы | `/opt/mtpctl/backup/mtpctl.db`, обновляется раз в сутки, только если новая копия цела |
| telemt | `/usr/local/bin/telemt`, `/etc/telemt/<сервер>.toml`, `telemt@<сервер>.service` |
| nginx | `conf.d/mtp-<домен>.conf`, `snippets/mtpanel.conf`, `stream.d/mtp-mask.conf`; заставки `/var/www/mtpctl/site/<домен>`, фото `/var/www/mtpctl/bg` |

## Управление

`mtpctl` без аргументов открывает меню:

```
  1. Доступ к кабинету (адрес, путь)        8. Применить и проверить сейчас
  2. Новый пароль кабинета                   9. Перезапустить службы
  3. Сменить путь кабинета                   10. Журнал
  4. Серверы                                 11. Обновить резервную копию
  5. Клиенты                                 12. Восстановить базу из копии
  6. Кто сейчас в сети                       13. Обновить mtpctl
  7. Состояние служб                         14. Удалить mtpctl
```

Всё то же доступно командами:

```sh
mtpctl server list | show <id> | add | edit | rm | check
mtpctl server add --title Друзья --domain example.org --ip <IP входа> [--sni ya.ru] [--devices N] [--default]
mtpctl client add <имя> [--server S[,S]] [--days N] [--devices N] [--quota 20G --period month] [--note …]
mtpctl client list | show <имя> [--qr] | servers <имя> S[,S] | renew | limits | note | enable | disable | rotate | delete
mtpctl online | traffic [<имя>] [--server S] [--range 24h|7d|30d|12m]
mtpctl web access | reset | path [ПУТЬ|--random] | passwd
mtpctl settings [--master-addr IP|DNS] [--panel-domain DNS]
mtpctl backup [файл] | restore <файл> [--access-from-backup] | status | restart | log | uninstall
mtpctl update [--check] [--force]
```

## Домен кабинета

По умолчанию кабинет открывается на домене каждого сервера по секретному пути. Лучше дать ему одну точку входа:
1. Сделайте A-запись отдельного домена на сам мастер, например `panel.example.org`.
2. Задайте этот домен в «Настройки» → «Кабинет», командой `mtpctl settings --panel-domain panel.example.org` или
   ключом `--panel-domain` при установке.

После этого:
- кабинет открывается только на `https://panel.example.org/<путь>/`, напрямую на порту 443 мастера;
- остальное на этом домене выглядит как только что установленный nginx: «Welcome to nginx!» на корне и его
  стандартная 404 на прочих адресах;
- домены серверов показывают только заставку;
- сертификат Let's Encrypt выпускается сам;
- проверки домена (DNS, сертификат, порт) видны там же в «Настройках».

Порт 443 на мастере должен быть открыт снаружи. Если кабинет задан доменом, он доступен сразу после установки, ещё до
добавления первого сервера.

**Пароль** меняется в «Настройки» → «Пароль администратора»: свой или кнопка «Сгенерировать» (16 случайных
символов). То же делают `mtpctl web reset` (новый случайный) и `mtpctl web passwd` (ввести свой).

**Секретный путь** («хеш») можно перегенерировать или задать свой: «Настройки» →
«Кабинет», `mtpctl web path` или меню `mtpctl`. Старый адрес при этом сразу перестаёт работать.

## Серверы и входы

**Сервер** — это вход. У него есть:
- название, которое видно в карточках клиентов;
- домен;
- IP входного хоста;
- при желании дополнительная маскировка: SNI из белых списков, например `ya.ru`.

**Клиент** — это один ключ и набор серверов. Ссылки строятся на каждый его сервер. Ключ работает только через
серверы, выбранные у клиента: у каждого сервера свой экземпляр telemt, поэтому подставить в ссылку чужой адрес
не получится. Лимит устройств считается на каждом сервере отдельно.

**Добавить сервер:** в кабинете «Серверы» → «+ Добавить сервер» или `mtpctl server add`. Дальше:
1. В DNS сделайте A-запись домена на IP входа.
2. На входном хосте от root выполните команду из «Подключение входа». Установщик скачается с GitHub:
   ```sh
   bash <(wget -qO- https://raw.githubusercontent.com/mittus/mtpctl/master/install.sh) slave --master <IP мастера> --port 8445
   ```
   Если GitHub с хоста недоступен, скачайте `install.sh` в кабинете и запустите `bash install.sh slave …` с теми же
   параметрами. Ключ `--auto-update` включает еженедельное обновление входа.
3. Нажмите «Проверить». Сертификат Let's Encrypt выпустится сам, как только домен будет указывать на вход.

Агент на мастере проверяет каждый сервер раз в 10 минут: telemt, firewall, DNS, сертификат, ответ входа,
маскировку. Результаты видны в карточке сервера.

**Пропал вход.** Поднимите новый хост, впишите его IP в карточке сервера, выполните на нём ту же команду и
поправьте A-запись. Ссылки по домену продолжат работать.

## Обновление

**Мастер.** Обновить можно тремя способами:
- в кабинете: «Настройки» → «Версия и обновление» → «Обновить до X»;
- командой `mtpctl update`;
- через меню `mtpctl`.

Версию в репозитории мастер проверяет сам раз в 12 часов. При обновлении он:
- скачивает исходники из того же репозитория и ветки, откуда ставился;
- обновляет код и кабинет;
- ставит telemt той версии, что зашита в `install.sh`, если она сменилась;
- пересоздаёт конфиги всех серверов.

База не трогается. Прокси и кабинет перезапускаются на несколько секунд.

**Входы обновляются сами у себя, а не с мастера.** Мастер не хранит ключей от входов: если взломают кабинет,
входные хосты не пострадают. На вход ставится почти неизменная пересылка портов, у неё своя версия
(`SLAVE_VERSION` в `install.sh`). Её поднимают только тогда, когда меняется то, что ставится на вход.

Обновить вход:
- **Вручную:** `mtpctl-entry` на входе. Команда скачивает свежий `install.sh` и переустанавливает вход, только если
  его версия выросла. `mtpctl-entry --force` переустанавливает в любом случае.
- **Автоматически:** `--auto-update` при установке входа включает проверку раз в неделю (`mtpctl-entry-update.timer`).
  Включайте, если доверяете репозиторию, из которого ставили: обновление выполняется от root.

## Восстановление базы без переустановки

Заменить базу копией на работающем мастере можно двумя способами:
- в кабинете: «Настройки» → «Восстановить из копии» (файл `.db`, до 200 МБ);
- командой `mtpctl restore файл.db`.

Что при этом происходит:
- копия проверяется, текущая база сохраняется в `/opt/mtpctl/backup/`;
- серверы, клиенты и трафик берутся из копии, а пароль, путь и домен кабинета остаются текущими;
- чтобы взять и их из копии, отметьте галочку в кабинете или добавьте `--access-from-backup`;
- конфиги telemt и nginx пересоздаются сразу.

## Перенос мастера

1. Скачайте копию базы: «Настройки» → «Скачать копию базы», или `mtpctl backup файл.db`. Можно взять и
   `/opt/mtpctl/backup/mtpctl.db`.
2. На новом хосте выполните:
   ```sh
   bash <(wget -qO- https://raw.githubusercontent.com/mittus/mtpctl/master/install.sh) --restore файл.db
   ```
3. Переустановите входы с новым адресом мастера. Если в «Настройках» адрес мастера задан DNS-именем, достаточно
   поменять его A-запись: входы перечитывают её каждые 5 минут.

Пароль и путь кабинета, серверы, клиенты и трафик переносятся вместе с базой. Сертификаты выпускаются заново
автоматически.

## Порты

**Входной хост:**

| Порт | Откуда | Зачем |
|---|---|---|
| 443/tcp | отовсюду | клиенты Telegram и заставка домена: TCP-пересылка на мастер с PROXY protocol |
| 80/tcp | отовсюду | проверка Let's Encrypt (HTTP-01) и редирект на https: пересылка на мастер |

Исходящие соединения с входа идут только на мастер: на порт своего сервера (8443, 8444, …) и на 80.

**Мастер, входящие:**

| Порт | Откуда | Зачем |
|---|---|---|
| 8443, 8444, … /tcp | только с IP входа своего сервера (правила ufw `mtpctl:<id>`) | telemt: по экземпляру на сервер, номер виден в карточке сервера |
| 80/tcp | с IP входов (`mtpctl:<id>:http`); отовсюду, если задан домен кабинета | Let's Encrypt и редирект на https |
| 443/tcp | отовсюду, только если задан домен кабинета | кабинет напрямую (`https://<домен кабинета>/<путь>/`) |
| 22/tcp | как у вас настроено | SSH, mtpctl его не трогает |

**Мастер, только 127.0.0.1** (снаружи закрыты):
- 8090 — бэкенд кабинета;
- 8445 — nginx: дополнительная SNI-маскировка;
- 8446 — nginx: заставки и кабинет за telemt;
- 9091, 9092, … — API telemt.

**Мастер, исходящие:**
- Telegram DC, 443/tcp (telemt ходит в DC напрямую);
- Let's Encrypt, GitHub (установка, обновление, telemt) и Wikimedia Commons (фото для заставок) — 443/tcp;
- сайты дополнительной маскировки, например ya.ru, — 443/tcp;
- DNS.

Если ufw на мастере включён, правила для портов серверов агент ставит и снимает сам. 80 и 443 для домена кабинета
откройте сами: `ufw allow 80,443/tcp`.

## Как это устроено

- **Кабинет** (`mtpctl-web`) работает от пользователя `mtpctl` на 127.0.0.1:8090. Он открывается по пути `/<путь>/` на
  домене кабинета, а если домен не задан — на домене любого сервера:
  - Корень домена — заставка, см. ниже. Ничего общего с кабинетом на ней нет.
  - Пароль хранится как PBKDF2-SHA256.
  - Cookie сессии привязана к пути кабинета, с флагами HttpOnly, Secure и SameSite=Strict.
  - Без сессии любой `/api/*` отвечает обычной страницей 404 nginx.
  - Попытки входа ограничены: 5 неудачных с одного IP за 15 минут.
- **Агент** (`mtpctl apply`, root) запускается из `mtpctl-agent.path` при каждом изменении в кабинете и из таймера раз
  в 10 минут.
  - Он приводит хост к базе: экземпляры telemt, правила ufw `mtpctl:<id>` (порт сервера и 80 — только с IP входа),
    конфиги nginx, сертификаты.
  - Перед использованием он заново проверяет каждое значение из базы.
  - Сам кабинет ничего не запускает от root.
- **Клиентов в telemt** синхронизирует кабинет через API telemt: при каждом изменении и раз в минуту, тогда же
  собирается трафик. Если сервер был недоступен, он догонит позже. Ручные правки в telemt откатываются к базе.

## Заставки доменов

Без секретного пути домен сервера выглядит как стартовая страница «фото дня», вроде экрана блокировки на Android:
- фото во весь экран, часы и дата;
- каждые 5 минут — следующее фото с плавной сменой;
- подпись автора и лицензии.

**Откуда фото.** Это фото дня Wikimedia Commons: горизонтальные JPEG с открытыми лицензиями (CC0, CC BY-SA, FAL).
Агент раз в сутки докачивает несколько штук в общий набор `/var/www/mtpctl/bg`, всего в наборе до 40 фото.
Без интернета остаётся прежний набор. Если фото нет совсем, показывается градиент. Сразу докачать:
`mtpctl apply --covers`.

**У каждого домена своё:** подборка из 12 фото, раскладка часов, цвет, favicon, `robots.txt` и страница 404.
Поэтому разные серверы по содержимому не связываются между собой.

```sh
python3 tests/selftest.py               # база, синхронизация, трафик, API кабинета (без root и сети)
bash tests/docker-e2e.sh [debian:13]    # контейнеры с systemd: установка одной строкой, вход, кабинет,
                                        # переезд мастера с ufw, удаление
```

В тестах telemt заменён на `tests/fake_telemt.py`: он повторяет нужную часть API и пересылку «не-Telegram» трафика
на сайт-заглушку.
